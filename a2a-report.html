EZStore A2A Application — Implementation Report

Quotation agent → order agent over the A2A protocol (bonus)

Scope: agent/quotation_agent/, agent/order_agent/ Model: gemini-3.1-flash-lite Date: 2026-10-28

What was built

The quotation agent now hands an order request to the order agent over A2A. The user stays in the normal quotation chat at http://localhost:3000/agent; there is no app switch and no special command. The order agent answers, the quotation agent relays the text, and a footer makes the A2A hop visible: 

（本回覆由訂單 Agent 透過 A2A 協定提供）
No new service, no frontend change, no new MCP tool. Both apps already live in the same agent container and port 8080. The change adds a second A2A endpoint and a deterministic handoff branch in the quotation graph.

Capture note. The two multi-turn screenshots were captured in the supported zero-cost mode (ORDER_AGENT_FAKE_LLM=1) because the 3.1 endpoint was returning 503 UNAVAILABLE at that moment. The A2A hop, context_id, MCP call and UI are the same as the real-model path; only the order classifier is the rule-based equivalent. The whole two-turn exchange uses 0 Gemini calls in that mode. The container is currently back on the real model (ORDER_AGENT_FAKE_LLM empty).

How it works

/agent  user message
  → quotation.guard                 deterministic, no model call
      ├─ order request  → order_handoff
      │                     │  A2A: card discovery + message/send
      │                     ▼
      │                  order_agent (same port, /a2a/order_agent)
      │                     ├─ classifier (1 call in real mode)
      │                     └─ MCP get_order / list_orders / order_summary
      │                     ▼
      └─ otherwise      → classify_intent → existing quotation flow
                              │
                              ▼
                           respond  (single user-facing text event)
  • Server: attach_a2a_routes() publishes an agent card and JSON-RPC endpoint for each app. The card URL is built from A2A_BASE_URL (default http://localhost:8080).
  • Client: call_remote_agent() resolves /.well-known/agent-card.json, creates an A2A client, sends a message/send, and returns the last non-JSON text from the stream.
  • Handoff: order_handoff calls the order agent with the quotation session id as context_id, so the order agent keeps its clarification state on the next turn.
  • Boundary: detect_order_request() excludes quotation operations, especially 報價單轉訂單, so the existing six quotation commands are unchanged.

API cost

InteractionModel calls
Order query containing a number1 (order classifier)
Order clarification turn (我要查訂單)1
Follow-up bare number (ORD-…)0 (pending intent + direct path)
A2A card discovery / JSON-RPC0
Quotation query (existing behavior)1
Deterministic mode (ORDER_AGENT_FAKE_LLM=1)0

Before this change, an order query sent to the quotation agent also cost one classifier call and then refused. The new path moves that one call to the order agent, so there is no net increase. The A2A transport itself never calls a model.

# ... demo ...
# back to the real model:
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d agent

The A2A routes are served by quotation_agent.fast_api_app:app (the Compose entrypoint), not by adk web / agents-cli playground. For local uvicorn, set A2A_BASE_URL to that port (for example A2A_BASE_URL=http://localhost:8099).

Known limitations

  • Provider availability: gemini-3.1-flash-lite returned 503 UNAVAILABLE during part of the session. The order agent's fallback text is intentional and the A2A hop still succeeds; the deterministic mode avoids the dependency for a demo.
  • Same-process A2A: both apps run in one container and the handoff calls the same uvicorn process over real HTTP. It demonstrates the protocol and card discovery, but it is not a separate deployment. A dedicated order-agent service would be the next step if independent scaling is required.
  • In-memory A2A task/session store: state is lost on restart.
  • Auto-generated card: the card contains the workflow's internal nodes as skills (16 entries). It is valid but noisy; a curated card would be a polish item.
  • Footer: the A2A footer is a demo aid; it is a single string in order_handoff and can be removed without touching the protocol path.
